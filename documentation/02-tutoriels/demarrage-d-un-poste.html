Démarrer un poste neuf

De la machine vide au poste qui affiche des données, en sept étapes. C'est aussi la recette de l'installateur sur site : chaque ligne dit qui l'exécute.

Durée : 10 min, base déjà créée par l'assistant Prérequis : PostgreSQL 14+ joignable, .NET 8 Desktop Runtime Renvois : T0, T1 et T7 du plan de qualification Aligné sur : commit 25bfcb7
Accueil › 02 · Tutoriels › Démarrer un poste neuf

Étapes

1
Exploitant Récupérer l'exécutable (dossier build ou installeur Velopack) et le poser sur le poste. Aucun fichier settings.json ne se copie : il contient host, base et utilisateur, et appartient au poste.
Contrôle Le premier lancement ne doit pas afficher de message d'erreur : sans réglages, le poste ouvre l'assistant.
2
Poste L'assistant réseau s'ouvre tout seul (ConnectionConfigWindow) : hôte, port, base, utilisateur, mot de passe, SSL éventuel.
3
Exploitant Bouton Tester la connexion. Le diagnostic est rédigé en français et cite la cause (SQLSTATE traduit), jamais une trame Npgsql.
À savoir Tester ne crée rien et n'enregistre rien : il Valide uniquement le trajet poste → serveur → base.
4
Exploitant Bouton Enregistrer et fermer. Le poste reteste, et si la base est absente il la crée, puis affiche : « La base a été créée sur le serveur. Elle est vide de tables : installez le schéma avec la migration EF… » — le nom de base est validé par whitelist avant tout appel, et un compte sans droit de création rend la main avec une phrase explicite. Les réglages partent ensuite dans %LocalAppData%\{NomApplication}\settings.json et le resolver de connexion se reactualise à chaud : pas besoin de redémarrer le poste.
Attendu Sur « Réglages enregistrés : ce poste est prêt. », la fenêtre se ferme seule après un instant. Si elle reste ouverte, l'enregistrement est bien passé quand même — le défaut était présent jusqu'à d65851a.
Ne pas sauter cette étape Une base que l'assistant vient de créer ne contient aucune table. Sans l'étape 5, l'écran de connexion affiche « la base est joignable mais ses tables sont absentes », et le temps réel est mort : le trigger de synchro fait partie de la migration, pas de la base.
5
Exploitant Dans un terminal, à la racine du dépôt du produit : 
dotnet tool install --global dotnet-ef --version 9.0.10   # une seule fois
dotnet ef migrations list --project Framework.Data      # contrôle de lecture
dotnet ef database update --project Framework.Data      # applique Initial + trigger
Toujours passer --project Framework.Data. Sans lui l'outil instancie le contexte hors DI et essaie de monter l'hôte de App.xaml.cs, qui plante sur la ResourceDictionary WPF.
6
Outil psql — ou pgAdmin si psql n'est pas dans le PATH (c'est le cas d'une installation PostgreSQL standard sous Windows : l'exécutable est dans C:\Program Files\PostgreSQL\<version>\bin) : 
SELECT tablename FROM pg_tables WHERE schemaname='public' ORDER BY tablename;
-- attendu : Comptes  Exemples  __EFMigrationsHistory

SELECT tgname FROM pg_trigger WHERE tgname LIKE 'TX_sync%';
-- attendu : TX_sync_Comptes  TX_sync_Exemples
Deux triggers, ou le temps réel ne marchera jamais et rien ne le dira à l'écran.
7
Exploitant Écran de connexion. Refermer l'assistant (croix) ou relancer le poste suffit : la fermeture relance le diagnostic de la table des comptes. Aucun login n'existe à ce stade — le socle ne semence personne. Deux états, lus dans le titre :
  • « Créer le premier compte » (table vide) : deux champs de plus, Nom complet et Confirmation. Vous inventez identifiant et mot de passe.
  • « Connexion » (table déjà peuplée) : les comptes existent déjà, par exemple parce que la base pointée n'est pas vierge.
Attendu Le rôle de ce premier compte est Administrateur, forcé dans le code — aucun choix n'est proposé, volontairement. À la connexion : votre nom et « Administrateur » dans la barre latérale, et les quatre entrées (Tableau de bord · Exemples · Comptes · Rôles et permissions). À ce stade le poste est seul au monde : la suite dit comment lui donner des collègues.

Donner des collègues à ce poste

Cinq lignes exécutées à l'écran, sans SQL : c'est l'écran Comptes (livré en 871c7ea) qui remplace la requête d'insertion. Le premier compte — Administrateur forcé — est seul tant que personne n'a créé le deuxième.

QuiFaireObserver
Exploitant Poste déjà connecté : entrée Comptes → bouton Nouveau compte → identifiant, nom complet, rôle, mot de passe (8 caractères minimum) + confirmation → Enregistrer Le rôle se choisit dans la liste fermée de la matrice ; la ligne apparaît avec la mention de l'opération en pied de liste.
Exploitant Sur un second poste (ou une seconde instance de l'exécutable) : assistant réseau, mêmes hôte / base / SyncChannel que le premier poste Le poste demande une connexion : les comptes existent déjà, le titre reste « Connexion » (l'amorce du premier compte est fermée).
Poste Se connecter avec le compte créé à l'étape précédente, rôle Lecteur par exemple La barre latérale de ce poste ne montre pas les mêmes entrées que celle de l'Administrateur : le rôle est lu à la connexion, pas copié d'un poste à l'autre.
Poste Sur le premier poste, écrire une ligne (écran Exemples ou Comptes) Le second poste recharge tout seul : le trigger TX_sync_* émet une notification que la barre latérale consomme. Deux postes sur des SyncChannel différents ne se voient jamais — c'est le premier réflexe à vérifier.
Exploitant Changer le rôle d'un compte ouvert sur un autre poste, puis reconnecter ce poste La session en cours garde son rôle jusqu'à la reconnexion : c'est le comportement voulu, pas un défaut de synchro.
Ce que l'écran Comptes ne fera jamais Il n'affiche pas et n'affichera pas les empreintes de mot de passe, il ne peut pas désactiver, supprimer ou changer le rôle du compte qui tient la session courante, et un mot de passe laissé vide en édition conserve l'empreinte existante. Lever un gel de connexion se fait par le bouton dédié, plus besoin de UPDATE "Comptes"….
Où voir qui porte chaque rôle L'écran Rôles et permissions déroule la matrice et, sous chaque carte, la ligne « Porté par : 1 compte : stage » (depuis 25bfcb7). Le bouton Recharger de cet écran sert à ça : créer un compte sur l'écran Comptes, revenir ici, recharger, et voir le nombre bouger. Un compte désactivé reste compté mais s'affiche « stage (désactivé) ».

Et si ça ne démarre pas

SymptômeCause la plus sûreVérification
L'assistant se rouvre à chaque lancement Réglages non écrits, ou fichier cabossé (le socle repart alors à vide, sans [ERR]) Exploitant ouvrir %LocalAppData%\{NomApplication}\settings.json
« la base est joignable mais ses tables sont absentes » Migration EF jamais appliquée sur cette base (42P01) — pas un problème réseau Exploitant étape 5 : dotnet ef database update --project Framework.Data, puis refermer l'assistant pour relancer le diagnostic
L'assistant reste ouvert après « Réglages enregistrés » Défaut corrigé en d65851a : EstConfigure ne levait pas PropertyChanged, la fermeture automatique était inatteignable Vérifier la version du poste ; en attendant, la croix (X) suffit — les réglages sont écrits
« No password has been provided but the backend requires one » Le champ mot de passe est vide : une PasswordBox ne se pré-remplit jamais, donc chaque réouverture de l'assistant part à vide Retaper le mot de passe avant de tester ; l'erreur blâme le serveur, ce n'en est pas une
« Server does not exist / connection refused » Hôte ou port erroné, service PostgreSQL arrêté, pare-feu Bouton Tester de l'assistant ; le message cite le SQLSTATE traduit
« password authentication failed » à la migration Le terminal ne relit pas les réglages enregistrés avant la commande Relancer l'assistant puis dotnet ef database update
Base absente et création refusée Nom de base hors whitelist (caractères non autorisés) Renommer en lettres/minuscules/tirets bas, réessayer
Compte gelé après trois échecs Anti-force-brute normal : 60 secondes, horloge du cadre Attendre, ou Exploitant poste ouvert en Administrateur : écran Comptes, sélectionner la ligne puis Lever le gel de connexion — la SQL UPDATE "Comptes" SET "EchecsConsecutifs"=0, "GelJusqua"=NULL; n'est plus nécessaire
Le poste affiche « 0 ligne » alors qu'un autre voit des données Trigger de synchro absent, ou SyncChannel différent entre postes Étape 6 ci-dessus ; puis pièges mesurés
Journal du poste

Serilog écrit dans %AppData%\{NomApplication}\Logs\app-{date}.log — un fichier par jour, quinze conservés, niveau Debug. Une erreur technique ne s'affiche jamais brute à l'écran : la trame complète est dans le journal, la phrase française est sur le poste.
