Copier le socle, le renommer à son nom, brancher son domaine et ses droits. Le cadre fournit la mécanique ; le produit écrit sa politique.

Le contexte du produit

public class AutoEcoleDbContext : FrameworkDbContext
{
    public AutoEcoleDbContext(DbContextOptions<AutoEcoleDbContext> options) : base(options) { }

    public DbSet<Eleve> Eleves => Set<Eleve>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(AutoEcoleDbContext).Assembly);
    }
}

base.OnModelCreating n'est pas décoratif : c'est là que le cadre pose le filtre de suppression logique et les conventions d'audit. L'oublier fait disparaître les droits et réapparaître les lignes supprimées.

Temps réel : la ligne à ne pas oublier

// dans la migration qui ajoute une table que les postes doivent partager
migrationBuilder.Sql(SyncNotifySql.Script("framework_sync", new[] { "Eleves" }));
Attention

dotnet ef migrations remove puis migrations add écrase le SQL du trigger ajouté à la main dans Initial. Le remettre dans la foulée : sinon les postes ne se notifieront plus rien, et rien ne le dira à l'écran.

La matrice du produit

// App.xaml.cs — à la place de MatriceParDefaut.Creer()
// ElevesDroits = la classe de clés du produit, même convention module.verbe
services.AddSingleton<IMatriceRoles>(_ => new MatriceRoles(new[]
{
    new RoleDefini("Direction", "Direction", new[] { Droits.Tout }),

    new RoleDefini("Secrétariat", "Secrétariat", new[]
    {
        Droits.TableauDeBordConsulter,
        ElevesDroits.Consulter,                       // "eleves.consulter"
        ElevesDroits.Cle(Droits.VerbeModifier),       // "eleves.modifier"
    }, new[] { "Accueil" }) { Description = "Inscrit, encaisse, ne supprime pas." },

    new RoleDefini("Accueil", "Accueil", new[] { ElevesDroits.Consulter }),
}));

Trois règles tiennent tout le RBAC du produit :

  • Un rôle que la matrice ne connaît pas ne donne aucun droit — y compris un rôle écrit à la main en base par erreur.
  • Peut() grise l'écran ; Exiger() refuse l'écriture. Les deux, toujours.
  • Une permission se déclare dans une constante (module.verbe), jamais en saisie libre au pied d'un bouton.
Ce que le socle ne donne pas

La liste est courte et volontaire : l'écran de gestion des comptes, la politique de droits métier, les vraies tables, les rapports du produit, le secret de licence. Voir cahier des charges § hors périmètre.
