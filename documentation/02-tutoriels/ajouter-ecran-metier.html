Ajouter un écran métier : copier la référence

ExempleEntity / ExempleViewModel / ExempleView ne sont pas une démo décorative : c'est le patron complet, droits et temps réel compris. On le copie, on renomme, on remplace les colonnes.

Pièce source : 3 fichiers + 1 configuration Durée : 30 min pour une première table À la fin : 0 erreur Release, tests verts, écran jouable
Accueil › 02 · Tutoriels › Ajouter un écran métier
Le patron a déjà été copié une fois

L'écran Comptes (ComptesViewModel / ComptesView / CompteLigne, ajouté en 871c7ea) est sorti de ce trajet sans dévier du patron : portée DI par opération, Exiger(…) dans la commande, garde de réentrance, ReactualiserSiNotreTableAsync. Comparer les deux fichiers est la façon la plus rapide de vérifier qu'une copie respecte le patron — et qu'elle y ajoute bien ses gardes métier.

Le trajet en sept étapes

1
Agent L'entité. Framework.Data/Entities/EleveEntity.cs : 
public class EleveEntity : EntityBase
{
    public string Nom { get; set; } = string.Empty;
    public string Categorie { get; set; } = string.Empty;
    public decimal Montant { get; set; }
    public string? Note { get; set; }
}
EntityBase apporte Id, CreatedAt, UpdatedAt, IsDeleted, DeletedAt. Ne jamais les redéclarer.
2
Agent La configuration et le DbSet. 
builder.ToTable("Eleves");
builder.Property(e => e.Nom).HasMaxLength(128).IsRequired();
builder.Property(e => e.Montant).HasPrecision(12, 2);
builder.HasIndex(e => new { e.Categorie, e.Nom }).HasName("IX_Eleves_Categorie_Nom");

// FrameworkDbContext (ou le contexte du produit)
public DbSet<EleveEntity> Eleves => Set<EleveEntity>();
Les longueurs et la précision du montant se déclarent ici, pas dans le formulaire : c'est la base qui décide, l'écran ne fait que l'annoncer avant l'échec.
3
Agent La migration, avec le trigger. 
dotnet ef migrations add AjoutEleves --project Framework.Data --startup-project Framework.WPF
Puis, dans le Up : 
migrationBuilder.Sql(SyncNotifySql.Script("framework_sync", new[] { "Eleves" }));
et dans le Down : DROP TRIGGER IF EXISTS "TX_sync_Eleves" ON "Eleves";
4
Agent Les permissions. Dans la classe de clés du produit, eleves.consulter / modifier / supprimer / exporter, puis dans MatriceParDefaut (ou la matrice du produit) qui les tient.
5
Agent Le ViewModel. Copier ExempleViewModel.cs en entier, renommer, et garder les quatre mécaniques :
MécaniquePourquoi elle est là
Portée DI par opération
_portes.CreateAsyncScope()		 Un écran ouvert huit heures ne retient pas une connexion du pool. Ne jamais mettre IUnitOfWork en champ.
_autorisation.Exiger(...) dans le try de la commande La seule vraie garde. Le bouton grisé n'est qu'un confort : Entrée, raccourci ou retour arrière contournent la vue.
Garde _rechargementEnCours Le bouton « Actualiser » et la notification d'un autre poste peuvent se croiser ; sans lui la liste finit dans un état qui ne correspond à aucune des deux requêtes.
Méthode publique ReactualiserSiNotreTableAsync(dto) Le demi de Receive découplé du Dispatcher WPF : c'est ce qui rend le temps réel testable sans fenêtre.
6
Agent La vue et les trois branchements. Copier ExempleView.xaml, changer les colonnes du DataGrid et le formulaire, puis : DataTemplate dans App.xaml, AddTransient dans App.xaml.cs, NavigationItem("Elèves", glyphe, typeof(EleveViewModel), ElevesDroits.Consulter) dans ShellViewModel._tousLesItems. Les deux boutons d'écriture se lient aux propriétés Bouton…Actif (droit et état), jamais à EstOccupe seul.
7
Agent Les tests. Copier ExempleViewModelTests.cs : validations, création/modification, suppression logique vérifiée en base (IgnoreQueryFilters()), notification d'un autre poste, refus d'écriture par rôle non autorisé. FakeSession + new AutorisationService(session, matrice) suffisent — aucune base réelle, aucune fenêtre.

Cinq pièges qui reviennent

GesteCe qui casse
Déclarer AddTransient<IAuthService> pour « propre » Le shell singleton ne voit jamais CurrentUser : chip utilisateur vide et tous les droits refusés, même pour un Administrateur.
Filtrer la liste à chaque frappe dans le champ Deux requêtes concurrentes et une liste qui ne correspond à rien. Le filtre s'applique sur le bouton « Actualiser ».
Oublier base.OnModelCreating dans le contexte produit Le filtre de suppression logique disparaît : les lignes supprimées ressurgissent.
Une clé de thème consommée sans exister dans Dark.xaml Écran illisible dès le basculement sombre — et le XAML compile très bien.
migrationBuilder.Sql(SyncNotifySql…) oublié Aucune erreur, aucun journal : la table n'est tout simplement jamais partagée entre postes.
